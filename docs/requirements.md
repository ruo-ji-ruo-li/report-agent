# 体检报告问答助手（report-agent）需求文档

## 1. 背景与目标

用户上传体检报告，系统对报告进行结构化解析、参考区间比对，检索医学知识库，最终产出：

1. **报告解读**：异常项逐项分析 + 分级健康建议
2. **复查计划**：结构化复查单（查什么、何时查、挂什么科）
3. **多轮追问**：针对报告与解读结果的持续对话

产品定位为**报告解读 + 健康建议**，不构成医学诊断。

## 2. 项目定位

- **企业内部 POC**：跑通全链路，架构按生产标准建设（重试、降级、可观测、可评测），但不做医疗合规认证、不接真实生产流量
- 当前阶段**无敏感数据**，全链路使用云端服务与云端 API
- 交付物为**纯后端 API**（FastAPI），前端由团队另行开发

## 3. 功能需求

### 3.1 报告输入与解析（P0）

- 支持两种输入：**电子版 PDF**（有文字层）；**拍照/扫描件**（需多模态模型解析）
- **手动录入关键指标**作为解析失败的降级入口，与上传共用同一数据模型
- 解析输出为结构化检验项：原始项目名、数值（或定性结果）、单位、参考区间、异常标记；以及报告元数据（机构、日期、受检人性别与年龄——区间判定的必要输入）
- 解析后必须做**归一化**：项目名对齐标准指标词典（别名映射）、单位换算、参考区间补全；映射不上的项标记 unknown 并继续，不中断流程

### 3.2 报告解读与建议（P0 核心）

- **区间判定由规则代码完成**：按（指标 × 性别 × 年龄段）查询标准参考区间做数值比对，识别危急值；**禁止用 LLM 判断数值高低**
- 逐异常项生成解读：数值含义、可能相关风险（**必须附知识库证据引用**）、分级建议（生活方式调整 / 定期复查 / 专科就诊 / 尽快就医）
- 支持**指标组合模式**识别（如代谢综合征类的多指标联合判断）
- 输出固定四段式结构：总体结论 → 逐项解读 → 分级建议 → 免责声明

### 3.3 多轮追问对话（P0）

- 基于已解读报告的追问；回答必须锚定本人报告数据与知识库
- Agent 只能调用受控工具（指标知识查询 / 知识检索 / 参考区间计算 / 本人报告查询），并有轮数上限，超限强制收敛作答
- 知识库未覆盖时**明确拒答**并建议咨询医生，禁止编造
- 流式输出（SSE），对话历史持久化，服务重启后可续

### 3.4 复查计划生成（P0）

- 基于解读结果生成结构化复查单：复查项目 / 时间窗 / 挂号科室 / 依据引用
- **模板化生成**，LLM 仅做措辞平滑且锁定在模板槽位内，不允许自由发挥

### 3.5 医学知识库（P0，先小规模示例）

- **指标知识图谱（事实源）**，需包含：
  - 指标节点：标准名、别名、单位、分类
  - 分性别、分年龄段的参考区间
  - 带**方向语义**的疾病提示关系（升高提示 / 降低提示分开建模）
  - 指标联合解读簇、指标组合模式、干预建议（分级）、建议科室
- **文档语料（派生检索层）**：临床释义 / 指南类文本切块入向量库，用于解释性内容召回
- 起步规模：**50~100 个高频指标的示例数据**，后续扩充；种子数据先经人工校对再入库
- 知识库更新以**实体/文档为单位增量更新**，不做全量重建

## 4. 非功能需求

### 4.1 安全与合规边界

- 禁止输出诊断结论、用药与剂量建议
- 危急值必须触发"尽快就医"强提醒
- 免责声明必含
- 预留数据脱敏与私有化切换的可能（配置化，本期不实现）

### 4.2 安全护栏

- **规则护栏**（纯代码、可单测）：诊断用语拦截、处方/剂量检测、必含元素校验、**数值一致性校验**（输出中的数值必须可溯源到解析结果）
- **二次 LLM 审核**：独立审核调用检查语义越界；**仅风险信号触发，非每轮必审**
- 审核不通过 → 带问题反馈重生成 1 次 → 仍不通过则输出安全降级版本（仅数值对照 + 强建议线下就医），并标记 `degraded`

### 4.3 降级与容错

- 解析失败（重试后）→ 引导改用拍照上传或手动录入，不产出半成品
- 检索层逐路降级：KG → 向量 → BM25 → 占位证据（建议线下咨询），任一层不可用系统整体仍可用
- LLM 调用超时/失败：指数退避重试；数据库写失败：告警但不阻塞用户响应

### 4.4 可观测与审计

- 节点级结构化日志（耗时）、LLM 调用追踪（LangSmith，可选开关）
- 护栏触发事件写入审计日志

### 4.5 评测与回归

- 标注测试报告集约 20 份 + 追问 QA 对约 30 条（含知识库外拒答题）
- 自动评测维度：解析准确率（归一后名称对齐 F1）、异常判定准确率（**规则比对层要求 100%**，单测全覆盖）、证据引用覆盖率、数值一致性通过率、安全指标（违规为零、拒答正确）
- 评测脚本进回归：管线改动后指标不得回退

## 5. 技术栈约束（已确认，设计时不得更换）

| 层 | 选型 |
|---|---|
| 编排 | **LangGraph**（必要处使用；对话线程用 Postgres checkpoint 持久化） |
| 主 LLM | **DeepSeek API** |
| 多模态解析 | **deepseek-v4-flash-vision-exp** |
| Embedding | **text-embedding-v3**（1024 维，DashScope） |
| 图数据库（云端） | Neo4j |
| 向量库（云端） | Milvus（HNSW，支持按 filter 增量更新） |
| 结构化存储（云端） | PostgreSQL（报告、解析结果、会话、复查计划、审计日志） |
| 后端 | FastAPI + Pydantic v2，SSE 流式 |
| 检索 | BM25（jieba）+ 向量 + KG 多跳，RRF 融合 |
| 配置 | 全部环境变量化（.env），提供 .env.example |

## 6. 已确认的方向性决策（供设计参考，无需重新决策）

1. **控制流分层混合**：报告解读与复查计划走**确定性管线**（每个节点可独立测试、有明确降级路径）；追问对话走**有界 Agent**（固定工具集 + 轮数上限）
2. **报告是结构化数据而非查询文本**：先解析归一化、规则比对，再逐异常项并发检索，最后综合生成
3. 参考区间判定、单位换算、危急值触发全部为**代码逻辑**；LLM 仅负责解释与成文
4. **KG 是知识事实源，向量库是派生检索层**（同 C9 结论）；KG 关系带方向语义
5. **不做** C9 式 LLM 意图路由器：解读/追问/计划三个入口在 API 层显式区分；C9 真正值得继承的是其"LLM 失败降级到规则"的思想与三路混合检索 + RRF 融合（见 `code/C9/rag_modules/`）
6. 交互模式：报告解读为**异步任务 + 轮询**（管线耗时 30s~2min）；追问为 SSE 流式

## 7. 验收标准（POC）

1. 电子 PDF 与拍照报告均可端到端完成：解析 → 异常清单 → 四段式解读 → 复查计划
2. 规则比对层单测 100% 通过；评测集上安全指标零违规
3. 至少一条降级路径可真实触发并演示（如 KG 不可用时仍能产出解读）
4. 追问对话对知识库外问题能正确拒答
5. 知识库增量更新可演示：新增/修改单个指标不触发全量重建
